# OrgDiff: агент сопоставления оргдокументов (русская версия)

Английская версия для жюри: [../README.md](../README.md). Инструкция запуска для администраторов: [../ЗАПУСК.md](../ЗАПУСК.md).

Рабочий прототип кейса «ИИ-агент „Анализ организационной структуры и функционала“».
Принимает комплекты документов «до» и «после» реорганизации в docx, pdf и xlsx,
находит изменения структуры, потери и частичные потери функций, переносы и слияния,
дубли и признаки конфликта интересов, и выдаёт заключение со ссылками на пункты
и дословными цитатами. Веб-экран для демонстрации, выгрузка заключения в docx.

## Демонстрация

```bash
uv sync
uv run app.py          # http://localhost:8765
```

На главной две зоны: перетащите файлы комплекта «до» и комплекта «после», либо нажмите
«Взять контрольный комплект организаторов», и файлы подставятся сами. Переключатели:
«проверять моделью» (gpt-4.1-mini, около трёх минут и $0.05) и «контрольный комплект»
(сверка с известными изменениями). Ключ OpenAI берётся из `../.env`; без ключа анализ
идёт по близости текстов.

Страница ожидания показывает этапы, счётчик обращений к модели и таймер. Отчёт начинается
со сводных цифр, дальше навигация по разделам, карточки «было / стало» с подсветкой
пропавшей части, источники и цитаты, рекомендации, в шапке кнопка «скачать заключение».

Контрольный комплект:

| Комплект | docx | pdf и xlsx |
|---|---|---|
| «До» | `../TZ/…редакция_8_обезличено.docx` | `testdata/положение_ред8.pdf`, `testdata/структура_ред8.xlsx` |
| «После» | `../TZ/…редакция_9_обезличено.docx` | `testdata/положение_ред9.pdf`, `testdata/структура_ред9.xlsx` |

Без веб-экрана:

```bash
uv run run.py --mode hybrid --verify --tau-dup 0.5   # контрольный комплект с эталоном, отчёт в report.md
uv run test_formats.py                               # парсеры pdf и xlsx против docx
uv run synth_test.py --n 16 --seed 7                 # 16 синтетических пар с известными изменениями
uv run synth_test.py --n 4 --seed 11 --verify        # то же с проверкой моделью
```

оргструктуры из рисунков, OCR для сканов.

## Результаты

### Контрольный комплект организаторов

Метрики по таблице из 31 истинного изменения в `orgdiff/golden.py`.

| Вход | Конфигурация | Полнота | Точность по потерям | Стоимость |
|---|---|---|---|---|
| docx | без модели | 87% | 75% | 0 |
| docx | hybrid + gpt-4.1-mini | 97–100% | 89–90% | $0.05 |
| pdf + xlsx | hybrid + gpt-4.1-mini, владельцы и КИ моделью | 97–100% | 100% | $0.06 |

### Документы, которых конвейер не видел

Контрольный комплект один, и на нём прототип настраивался. Чтобы проверить работу на
других документах, `orgdiff/synth.py` собирает положения из пула реальных формулировок
с 3–6 департаментами и вносит в «после» 3–6 известных изменений восьми типов: потеря,
частичная потеря, перенос, дублирование, создание и упразднение департамента,
переформулировка без смены смысла, вставка пункта со сдвигом нумерации. Часть пар
конвертируется в PDF через Word. Ожидания сверяются с выводами автоматически.

| Прогон | Изменений | Полнота | Ложных потерь |
|---|---|---|---|
| 16 пар, без модели, 4 из них в PDF | 126 | 88% | 0 из 48 заявленных |
| 4 пары, с моделью gpt-4.1-mini | 23 | 91% | 0 из 12 заявленных |

По типам без модели: создание 9/9, упразднение 6/6, переформулировка 6/6 без единой
ложной потери, частичные 8/9, потери 56/64, переносы 9/11, дубли 10/13, вставки 7/8.
Пропуски без модели это в основном пункты, которым нашёлся похожий кандидат и которые
ушли в очередь «частично покрыто» вместо «потеря»; с моделью очередь разбирается.
Полный разбор по сценариям в `reports/synth-hybrid.md` и `reports/synth-verified.md`.

## Что синтетика нашла и что закрыто

- **Подстрока в аббревиатуре.** «ДАД» совпадала внутри «ДАДО», и функция одного
  департамента засчитывалась слиянием в другой. Сравнение теперь по границам слов.
- **Короткий хвост невидим для порога.** Если у функции отрезано «Главному аудитору»,
  близость остаётся выше порога и пара считалась неизменённой. Теперь у высокой близости
  сравниваются основы слов, и пропавшее значимое слово отправляет пару на проверку модели.
- **Гонка за кеш эмбеддингов.** Два процесса писали и читали один pickle, чтение
  обрывалось. Запись стала атомарной, битый файл читается как пустой.
- Три ошибки самого генератора: создание и упразднение одного департамента в одном
  сценарии, ожидание потерь только обязанностей при упразднении, но не прав, и старые
  PDF от прошлого прогона, сходившие за результат конвертации.

## Как это работает

1. Документ режется на пункты с составными идентификаторами, владельцем из вводной фразы
   блока и модальностью. PDF сначала склеивается из строк в абзацы.
2. Две последовательности пунктов выравниваются динамическим программированием со
   слияниями и разделениями по гибридной близости из лексики и эмбеддингов.
3. Разрывы классифицируются: потеря, частичное покрытие, перенос, слияние в общий блок,
   снятие с владельца. Владелец это множество ролей.
4. Спорные места решает модель голосованием трёх вызовов по строгой схеме с цитатами.
   Цитаты сверяются с текстом, «пропавшая часть» обязана быть в старом пункте и
   отсутствовать в новом по основам слов. Вердикт без подтверждения ничего не меняет.
5. Дубли ищутся внутри новой редакции кластеризацией с подтверждением моделью.
6. Заключение и рекомендации собираются из выводов, ничего не пересчитывая.

## Файлы

- `app.py` веб-экран, `run.py` CLI с эталоном, `test_formats.py` проверка парсеров,
  `synth_test.py` прогон по синтетическим парам, `make_testdata.py` генерация xlsx.
- `orgdiff/`: `load.py` форматы, `parse.py` пункты, `structure.py` оргструктура,
  `similarity.py` близость и кеш, `align.py` выравнивание, `analyze.py` классификация,
  `verify.py` вопросы к модели и заслоны, `pipeline.py` сквозной прогон,
  `report.py` заключение, `synth.py` генератор документов, `golden.py` эталон.
- `testdata/` тестовые pdf и xlsx, `reports/` финальные отчёты и пример
  `заключение_pdf_xlsx.docx`.
