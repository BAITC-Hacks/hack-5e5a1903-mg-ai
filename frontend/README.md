# frontend

Дашборд прогноза выработки ВЭС: восемь разделов на данных из `/api/forecast/*`.
Статика без сборки — ни npm, ни node_modules, ни бандлера. Файлы отдаются как есть,
страница работает офлайн: React, рантайм шаблонов, шрифты и картинка лежат рядом.

## Что где лежит

| Путь | Что это |
|---|---|
| `index.html` | страница целиком: разметка восьми разделов, экран входа, адрес API |
| `api.js` | клиент API: токен, заголовок `Authorization`, таймаут, разбор ошибок |
| `app.js` | вся логика: загрузка данных, состояния экрана, сборка значений для разметки |
| `vendor/react.js`, `vendor/react-dom.js` | React 18 UMD, локальные копии вместо CDN |
| `vendor/dc-runtime.js` | рантайм шаблона: разбирает разметку внутри `<x-dc>` и рисует ее React'ом |
| `fonts/*.woff2` | Onest и JetBrains Mono, подключены из `@font-face` в `index.html` |
| `img/site-satellite.jpg` | снимок площадки для раздела «Объект» |

Разметка и логика разделены намеренно: в `index.html` нет вычислений, в `app.js` нет HTML.
Рантайм требует, чтобы класс компонента лежал внутри страницы, поэтому в конце
`index.html` остался мост из шести строк, который зовет `ZHEL.mount` и `ZHEL.view`.

## Адрес API

Задается **в одном месте** — в начале `index.html`:

```html
window.API_BASE = window.API_BASE || "/api";
```

По умолчанию запросы уходят на тот же источник, что и страница: nginx раздает эту папку
и проксирует `/api` на backend, поэтому CORS не нужен и порт backend в адресе не участвует.
Для отладки без nginx в том же блоке есть закомментированная строка с полным адресом
(`http://localhost:8000/api`) — раскомментируйте ее и поправьте порт.

## Как открыть локально

Через стек целиком:

```bash
docker compose up -d --build
# страница на порту, который отдает сервис статики
```

Без Docker, только фронт (любой статический сервер из корня этой папки):

```bash
cd frontend
python -m http.server 3000
# открыть http://localhost:3000, API_BASE поменять на адрес backend
```

Файл можно открыть и двойным щелчком (`file://`): страница нарисуется, но запросы
к API браузер заблокирует, и вы увидите экран входа с понятной ошибкой, а не белый экран.

## Вход

`POST /api/auth/login` с телом `{"email": "...", "password": "..."}`. Токен кладется
в `localStorage` под ключом `zhel.access_token` и уходит в заголовке
`Authorization: Bearer <token>` во всех последующих запросах. Ответ `401` на любом
запросе стирает токен и возвращает на экран входа. Кнопка «Выйти» в шапке делает то же.

## Откуда данные на каждом разделе

| Раздел | Запрос |
|---|---|
| шапка, выбор дня | `GET /api/forecast/issues` |
| Обзор | `GET /api/forecast/{дата}` |
| Диспетчер | `GET /api/forecast/{дата}/dispatch?risk=0.20` |
| Агент | `GET /api/forecast/{дата}/agent-log` |
| Бэктест | `GET /api/forecast/backtest` |
| Погода | `GET /api/forecast/{дата}/weather` |
| Модель | `GET /api/forecast/model` |
| Объект | `GET /api/forecast/site` |
| кнопка «Пересчитать» | `POST /api/forecast/{дата}/recompute` |

Формы ответов описаны в [../docs/api-contract.md](../docs/api-contract.md), источник
истины — схемы в `backend/src/modules/forecast/schemas.py`.

Раздел запоминается в адресе (`index.html#dispatch`), поэтому ссылкой на конкретный
экран можно поделиться.

## Честность данных и состояния экрана

- Каждый ответ API несет поле `data_source`. Пока оно `stub`, под шапкой висит плашка
  «Демонстрационные данные» с перечислением того, что именно пришло из заглушки.
  Пропадет она сама, когда бэкенд начнет отдавать `live`.
- Все числа на экране приходят из ответов. Ничего не досчитывается «по формуле из головы»:
  агрегируются только строки прогноза по турбинам в ряд по станции.
- Пустого экрана быть не должно. Предусмотрены три состояния: идет загрузка,
  ошибка запроса (текст на русском, технический код и кнопка «Повторить запрос»),
  пустые данные (что именно пришло пустым).
- Смена дня в шапке и ползунок риска на «Диспетчере» перезагружают только то,
  что относится к выбранному дню; ответ, опоздавший после смены дня, отбрасывается.

## Ограничения

- Факт SCADA рисуется, только если он есть в ответе (`actual`): за будущие сутки его нет.
- Обновление токена (`refresh_token`) не используется: по истечении срока пользователь
  входит заново.
- Кнопка «Пройти все дни» листает выпуски по одному, каждый шаг — это запрос к API.
