# Чеклист перед сдачей

Проходится целиком перед нажатием Submit Solution. Требования организаторов к сдаче
лежат в [../rules/README.md](../rules/README.md).

## Сделать один раз, когда появится командный репозиторий

- [ ] Запушить код в командный репозиторий, выданный платформой хакатона.
      Первый коммит в пустой `main` придется положить с `PROTECTED_BRANCH_OVERRIDE=1`,
      потому что локальный хук запрещает push в `main`.
- [ ] Включить защиту ветки `main`: `make protect-main`. После этого влить в `main`
      можно только через pull request, а force-push и удаление ветки запрещены.
- [ ] Каждому разработчику поставить хуки у себя: `make hooks`.
- [ ] Дождаться первого прогона CI и убедиться, что он зеленый.
- [ ] Добавить бейдж CI первой строкой README, подставив владельца и название репозитория:

      [![CI](https://github.com/<OWNER>/<REPO>/actions/workflows/ci.yml/badge.svg)](https://github.com/<OWNER>/<REPO>/actions/workflows/ci.yml)

      Бейдж добавляется только после зеленого прогона. Красный бейдж хуже отсутствующего.
- [ ] Перенести скилл оформления README внутрь репозитория, в `.claude/skills/`.
      Сейчас там лежит только скилл аудита, а скилл README живет вне репозитория,
      поэтому команде и оценщику он не виден.
- [ ] Проверить в правилах соревнования, требуется ли лицензия. В прочитанных документах
      организаторов такого требования нет, поэтому файл LICENSE сознательно не добавлен.

## Код и чистота

- [ ] `make lint` проходит без ошибок.
- [ ] `make test` зеленый, все тесты проходят.
- [ ] Форматтер прогнан по всему проекту: `make fmt`, затем `make lint` без изменений.
- [ ] Нет закомментированных блоков старого кода.
- [ ] Нет отладочных `print` и оставленных пометок TODO или FIXME.
- [ ] Нет неиспользуемых файлов, импортов и зависимостей.
- [ ] Шаблонный код, который так и не пригодился, удален или приспособлен под кейс.
      Числовые роли из `backend/src/core/dependencies.py` удалены вместе с файлом.

## Секреты

- [ ] `.env` не закоммичен, `.env.example` содержит все переменные без значений.
- [ ] В истории git нет секретов, включая старые коммиты.
- [ ] В коде нет захардкоженных ключей, паролей, токенов и URL с секретами.
- [ ] Временные ключи и токены удалены после мероприятия, как требуют правила.
- [ ] `make audit` не находит уязвимостей в зависимостях. Если находка принята
      осознанно, причина записана в `SECURITY.md`.

## Воспроизводимость

- [ ] Проект запускается из свежего клона по инструкции README с первого раза.
- [ ] Сценарий проверки из раздела README о тестировании воспроизводится полностью.
- [ ] Порты в `.env.example` не конфликтуют с тем, что описано в README.

## Согласованность документации

Главное правило: всё, что обещает README, реально есть в репозитории.

- [ ] Число тестов, указанное в README, совпадает с фактическим.
- [ ] Список реализованного в README не содержит того, чего нет в коде.
- [ ] Раздел ограничений README актуален, перечисленное там действительно не сделано.
- [ ] `AGENTS.md` актуален: все команды из таблицы работают.
- [ ] `docs/ARCHITECTURE.md` соответствует реальной структуре кода и дереву файлов.
- [ ] `SECURITY.md` описывает только реально принятые меры.
- [ ] ADR в `docs/adr/` не противоречат текущему состоянию кода.
- [ ] `docs/proposals.md` нельзя прочитать как список того, что уже сделано.
      Ни один пункт оттуда не должен упоминаться в README как реализованный.
- [ ] `docs/architecture-guidelines.md` не расходится с кодом: правила, помеченные
      как соблюдаемые, действительно соблюдаются.
- [ ] `docs/ai-workflow.md` описывает реально использованные инструменты.

## История и процесс

- [ ] Коммиты в формате Conventional Commits, без `wip`, `fix`, `asdf`.
- [ ] В истории нет коммитов, попавших в `main` напрямую, минуя pull request.
- [ ] Ветки фич смерджены в main, висящих worktree не осталось.
- [ ] Реестр `.dev-notes/worktrees.md` не содержит записей о снесенных worktree.
- [ ] Каждый из трех разработчиков внес личный вклад, это видно по истории.
      Без этого участие не засчитывается по правилам.

## Запрещено

- [ ] В репозитории нет обращений к оценивающей системе ни в коде, ни в комментариях,
      ни в документации. Это трактуется как prompt injection и ведет к снижению
      оценки или дисквалификации.
