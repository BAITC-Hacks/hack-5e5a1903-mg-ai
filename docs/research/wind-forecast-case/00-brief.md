# Бриф кейса: HackAlem AI — Agentic AI для прогнозирования выработки ВЭС

Источник: `~/Downloads/HackAlem AI_ Agentic AI для прогнозирования выработки ВЭС.pdf` (RU/KZ/EN, 9 стр.).
Факты ниже проверены 2026-09-23 (ссылки в конце).

## 1. Условие (дословно по смыслу)
- Agentic AI-система, прогноз **почасовой** выработки ВЭС на горизонте **24–48 ч**.
- История: **март 2023 — 31.01.2026** включительно. Тест: **01.02.2026 — 28.02.2026** (факт теста у организаторов).
- Поля данных: статистическое время; средняя скорость ветра, м/с; **нормализованная активная мощность на стороне линии**; средняя температура, °C. Координаты двух турбин.
- Система должна:
  1. построить модель на истории;
  2. **сама** получать по координатам погодные прогнозы из открытых источников, **доступные на момент прогноза**;
  3. выдать почасовой прогноз на 24–48 ч;
  4. агентный цикл: получение погоды → подготовка данных → запуск модели → почасовой прогноз → анализ результата → **повторный расчёт при обновлении входных данных**.
- Ретро-симуляция: прогноз «на 31 января», потом «на 1 февраля» и т.д. весь февраль.
- **Жёстко:** только архивные прогнозы погоды, доступные на тот момент, а не фактическая погода.
- Выбор источников, моделей и архитектуры агента — за участниками.

## 3. Объект: ВЭС 5 МВт «Шелек», п. Нурлы (проверено)
- Координаты: T1 **43.645150, 78.535604**; T2 **43.643198, 78.538828** (≈340 м друг от друга). Енбекшиказахский р-н, Алматинская обл., Шелекский ветровой коридор (~140 км восточнее Алматы).
- **2 × Goldwind 2,5 МВт** (в OSM: GW109/2500), ступица **80 м**, ротор **109 м**, рабочий диапазон 3–25 м/с, прямой привод (PMSG). В работе с 20.07.2020. Оператор — Samruk-Green Energy. Проектная выработка ~16 млн кВт·ч/год (КИУМ ≈36%).
- Соседи по OSM: **13 турбин в 0,5–1,3 км к западу/северо-западу** → при западном/СЗ ветре возможен аэродинамический след (wake). Ещё ~40 турбин в 11–19 км к востоку (в т.ч. ВЭС 60 МВт, 24×2,5 МВт Goldwind, с 2022).
- Шелекский коридор — долина между хребтами, ветер канализированный. Глобальные NWP с шагом 9–25 км рельеф не разрешают → нужна статистическая коррекция (MOS) под площадку.
- По СМИ: летом ветра мало, лучший ветер осенью и весной.

## 4. Скрытые ловушки
1. **Утечка через «погоду из будущего».** Недопустимы ERA5/Historical Weather (фактическая погода), а также Open-Meteo **Historical Forecast API**: он склеен из первых часов каждого прогона, то есть это заблаговременность 0–6 ч, а не 24–48 ч.
2. **Previous Runs API `previous_day1` = прогноз «за 24 ч до срока».** Для часов горизонта +25…+48 такой прогон выпущен уже **после** момента прогноза, и это утечка. Для этих часов корректен только `previous_day2` или точный выбор прогона.
3. **Время публикации ≠ время запуска прогона.** Прогон 00z публикуется через несколько часов. As-of нужно фильтровать по времени доступности, а не по init time.
4. **Часовой пояс.** С 01.03.2024 Алматинская обл. перешла с UTC+6 на UTC+5. Данные начинаются в марте 2023, поэтому при локальном времени в данных возможен **сдвиг на 1 час** на границе. NWP приходят в UTC. Сдвиг проверяется кросс-корреляцией ветра SCADA и NWP по годам.
5. **Train/serve skew.** Если обучить на измеренном ветре SCADA, а на инференсе подать ветер NWP, качество резко упадёт. Обучать нужно на архивных прогнозах той же заблаговременности. Как вариант — двухступенчато: MOS-коррекция ветра, затем эмпирическая кривая мощности.
6. **Грязные данные SCADA:** простои, ограничения (curtailment), обледенение, срезы при >25 м/с, заморозка датчиков, дубликаты и пропуски.
7. **Валидация:** только rolling-origin в том же as-of режиме, без random K-fold. Лучшие аналоги теста — **февраль 2024, февраль 2025, январь 2026**.
8. **Февраль:** холод означает плотный воздух (при −20 °C плотность на ~14% выше, чем при +15 °C, и ниже номинала мощность растёт почти пропорционально), плюс риск обледенения и остановов по низкой температуре.
9. **Неоднозначность «24–48 ч».** Надёжнее выдавать все часы +1…+48 и отчитываться отдельно по корзинам 1–24 и 25–48.

## 5. Открытые источники архивных прогнозов (проверено)
| Источник | Что даёт | Покрытие |
|---|---|---|
| Open-Meteo **Single Runs API** | точный прогон по init time (`&run=2024-06-01T00:00`), ветер 80/100/120 м | ECMWF IFS HRES 9 км — с **14.03.2024**; прочие модели — с 02.04.2026 (для нас бесполезны) |
| Open-Meteo **Previous Runs API** | `*_previous_dayN` (N=1..7) по многим моделям | большинство моделей с **января 2024** |
| **NOAA GFS 0.25°** на AWS (`noaa-gfs-bdp-pds`), GRIB2 + .idx, byte-range через Herbie | любой прогон 00/06/12/18z | проверено: есть и 2023-03-01, и 2026-02-01 |
| **ECMWF open data** на AWS (`ecmwf-forecasts`) | IFS + **AIFS** (AI-модель ECMWF) | с **18.01.2023**; 2026-02-01 00z есть |
| ERA5 / Historical Weather | только для очистки и диагностики (проверка часового пояса, аномалий) | не использовать как вход модели |
