# ADR 0006: Фронтенд как статика за nginx, он же единая точка входа

## Статус

Принято. Решение команды 23.09.2026 в ответ на предложение из
[../proposals.md](../proposals.md).

## Контекст

Появился интерфейс: готовый дашборд из восьми страниц на React, который нужно
показать судье и подключить к нашему API. Требование организаторов простое:
проект поднимается с чистого клона одной командой и работает.

Три ограничения определили выбор:

- судья может открывать проект без интернета, значит ни один ресурс не должен
  тянуться из сети во время работы;
- пять часов на всё, значит время на настройку сборки фронтенда это время,
  отнятое у самого кейса;
- интерфейс и API на разных портах означают CORS, а на машинах разработчиков
  порты сдвинуты, и адрес API пришлось бы менять руками.

## Решение

Фронтенд лежит в `frontend/` как готовая статика: HTML, локальные React, ReactDOM
и рантайм дашборда, локальные шрифты. Сборки нет, `npm` и `node_modules` в проекте
не появляются.

Отдает статику отдельный сервис `frontend` на `nginx:alpine`, и он же проксирует
`/api` на backend внутри сети compose. Интерфейс и API оказываются на одном
источнике, поэтому адрес API в коде фронтенда относительный (`/api`), CORS не нужен,
а порт backend в ссылки не попадает.

## Альтернативы

- **Отдавать статику самим FastAPI через `StaticFiles`.** Ни одного нового сервиса,
  но приложение живет с `root_path="/api"`, поэтому интерфейс оказался бы на
  `/api/ui`, а backend начал бы обслуживать статику вместе с запросами API.
- **Полноценный Vite и React со сборкой.** Привычный стек и удобная разработка,
  но это `npm`, `node_modules`, еще один шаг сборки в образе и `npm audit`
  в проверке зависимостей. На пять часов слишком дорого.
- **Открывать `index.html` файлом с диска.** Работает, но тогда интерфейс не
  поднимается через `docker compose up`, а это прямое требование к артефактам.

## Последствия

Плюс: одна точка входа для судьи, отсутствие CORS, отсутствие шага сборки,
работа без интернета. Порт `FRONTEND_PORT` из `.env` получает смысл, которого
раньше не имел.

Минус: еще один сервис в `docker-compose.yml` и конфиг nginx, который надо
держать в согласии с путями API. Правка фронтенда это правка статики руками,
без горячей перезагрузки и без системы сборки, поэтому большие изменения
интерфейса обходятся дороже, чем в обычном React-проекте.

Ограничение области: nginx здесь только раздает статику и проксирует `/api`.
Балансировка между репликами backend, ограничение частоты запросов и HTTPS
остаются предложением в [../proposals.md](../proposals.md) и не внедрены.
