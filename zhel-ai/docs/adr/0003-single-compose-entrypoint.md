# ADR 0003: Один compose-файл в корне как единственная точка запуска

## Статус

Принято

## Контекст

После заливки шаблона в репозитории оказалось три compose-файла: один в корне и два
внутри `backend/`. Файлы шаблона жестко прописывали порты `8000:8000` и `5432:5432`
и имена контейнеров `app_backend` и `app_db`. Это ломало слоты портов из
[ADR 0002](0002-worktree-per-feature.md): два worktree одновременно не поднялись бы.

Дублировались и настройки: у backend был свой `.env.example`, `.gitignore` и `Makefile`,
расходящиеся с корневыми. Для оценки репозитория это шум, а для команды источник
расхождений.

## Решение

Единственная точка запуска — `docker-compose.yml` в корне. Он собирает `./backend`
и публикует порты из переменных окружения. Рядом лежит `docker-compose.dev.yml`
как оверлей для разработки: монтирует код внутрь и запускает uvicorn с автоперезагрузкой.

Из `backend/` удалены оба compose-файла, `Makefile`, `.env.example` и `.gitignore`.
Их роль перешла к корневым файлам. `backend/README.md` сокращен до ссылки на
[../backend.md](../backend.md), чтобы не было второго конкурирующего описания проекта.

Миграции запускаются внутри контейнера через `docker compose exec`, а не на хосте.
Раньше цели шаблона требовали `uv` на хосте и опубликованный порт БД.

## Альтернативы

- **Оставить compose внутри backend.** Тогда корневой compose нужен был бы только для
  frontend, и поднять весь проект одной командой не получилось бы.
- **Использовать `docker-compose.override.yml` для разработки.** Compose подхватывает
  такой файл автоматически, и тогда режим разработки стал бы режимом по умолчанию,
  в том числе у судьи. Явный `-f docker-compose.dev.yml` предсказуемее.
- **Параметризовать compose-файлы шаблона теми же переменными.** Убрало бы конфликт
  портов, но оставило бы три файла и дублирование настроек.

## Последствия

Плюс: `docker compose up -d --build` из свежего клона поднимает весь проект. Это же
проверяется в CI сборкой образов, поэтому расхождение `.env.example` и compose
обнаружится автоматически.

Минус: команды шаблона из его документации больше не работают, поэтому разбор backend
описывает уже наш способ запуска. Тесты и линтер при этом запускаются не в контейнере,
а через `uv`, теми же командами, что в CI. То есть правило «всё через compose» относится
к запуску приложения, но не к тестам.
