# Правила хакатона HackAlem AI — выжимка

Источник: три PDF в этой папке. Здесь только то, что влияет на работу.

## Instructions_for_HackAlem_AI_Participants.pdf

- Активировать доступ к Codex, OpenAI API и NVIDIA (отдельный файл активации). **Ключи в GitHub не публиковать.**
- Выбрать **один кейс** из трека, все решать не нужно. Изучить требования и критерии оценки кейса.
- Распределить роли в команде.
- Способ разработки любой, главное: **использовать AI-агента** и держать финальный код в **командном GitHub-репозитории, созданном платформой**.
- Реализовать обязательные требования кейса **за 5 часов** и протестировать основной флоу: от входных данных до результата.
- Подготовить README (на английском). Обязательные разделы:
  1. Название проекта
  2. Что решает и для кого
  3. Что реализовано
  4. Как работает (основной user flow)
  5. Технологии (языки, фреймворки, AI-модели, API, внешние сервисы)
  6. Архитектура (компоненты и их взаимодействие)
  7. Установка и запуск (пошагово, с командами)
  8. Как протестировать (сценарий, который жюри может повторить)
  9. Данные и интеграции
  10. Ограничения (что не сделано)
  11. Ссылка на деплой, если есть
  - README только по фактам из репозитория, ничего не выдумывать.
- Запушить последнюю версию в командный репозиторий.
- Сдача: страница треков, выбрать кейс, **Submit Solution**, название и описание. Можно обновлять до дедлайна. Видео: https://youtu.be/qFA0tuMcKPg

## Инструкция по кибербезопасности.pdf

Что важно для кода и репозитория:

- **Секреты (API-ключи, токены, пароли) не хранить в коде, репо, презентациях, чатах.** Только `.env`, который в `.gitignore`.
- Перед публикацией проекта проверить его на наличие паролей и токенов.
- Репозиторий приватный, доступ только команде и организаторам.
- Проверять используемые библиотеки. Никакого вредоносного кода, скрытых аккаунтов, бэкдоров.
- Не использовать реальные продакшн-данные без разрешения. Использовать только данные и сервисы, разрешенные организаторами.
- В AI-сервисы не передавать конфиденциальную информацию. Результаты AI проверять самостоятельно.
- После хакатона удалить временные ключи и локальные копии данных.

Что важно на площадке:

- Только официальный Wi-Fi хакатона. **Раздача интернета с телефона, свои роутеры и хотспоты запрещены.**
- Сеть общая и недоверенная: HTTPS везде, не лезть к устройствам и проектам других команд.
- Запрещено без разрешения: сканировать сеть, перехватывать трафик, брутфорс, нагрузочные / DoS-тесты, обход лимитов.
- Устройство: обновленная ОС, блокировка экрана, антивирус, не оставлять разблокированным.
- Об инцидентах (утечка ключа, потеря устройства, подозрительный вход, найденная уязвимость) сразу сообщать организаторам. Самому не эксплуатировать и не скрывать.
- Нарушение: блокировка сети, отзыв ключей, удаление проекта, дисквалификация.

## Правила зачета участия.pdf

- Вход по одному, QR на бейдже сканируется. Чужой бейдж запрещен, передавать свой нельзя.
- После старта **пересаживаться нельзя**, даже внутри сектора. За сектором закреплен стюард.
- Личные выходы: **суммарно 60 минут** на весь хакатон. Перед выходом и после возвращения сообщать стюарду, бейдж сканировать на выходе и входе.
- **Последний час** нужно быть в зоне хакатона, выходы запрещены (экстренно до 5 минут с разрешения стюарда).
- **Каждый участник должен внести личный вклад** в проект. Проект создается в рамках хакатона.
- Технические вопросы: поднять руку, подойдет ментор.
- Участие не засчитывается, если: не вернулся до старта, чужой бейдж, нет личного вклада, отсутствовал более 60 минут, отсутствовал в последний час, ушел до конца, пересел.
